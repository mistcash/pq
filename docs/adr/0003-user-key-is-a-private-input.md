# The User Key is a private input, so opening a Channel hides its recipient

Opening a Channel proves that its Encrypted Channel Key is a Kyber512 encryption of the Channel Key behind its Channel Key Hash. We considered verifying that against the recipient's registered User Key, with a curve point precomputed at registration that folds the User Key's public inputs into the verifying key. But then openChannel has to name the recipient, and a point the sender supplies unchecked identifies them just the same. So the User Key is a private input, and the proof only shows the Channel Key was encrypted to some Kyber512 key. A sender who encrypts to the wrong key only breaks their own Channel. Recipients pay for this by trial-decrypting every Channel. The Encrypted Sender is outside the proof, so like the old join links it doesn't prove who opened the Channel.
