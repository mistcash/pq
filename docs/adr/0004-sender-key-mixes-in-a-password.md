# The Sender Key mixes in a Password, so a quantum attacker can't re-derive it

ADR-0002 derived the Sender Key from a wallet signature alone. But registering exposes the wallet's public key on-chain. A quantum attacker who recovers the private key from it can re-sign the fixed message: any wallet that passes the double-sign check signs deterministically. With that signature they can read every Channel from ciphertexts that stay on-chain forever (#44). So the Sender Key is now H(signature, Password stretched by Argon2id), using RFC 9106's second recommended parameters (t=3, 64 MiB, p=4) salted with the signature. Argon2id is the one hash outside Poseidon2 (ADR-0001), because stretching a password needs a memory-hard function, and it runs in the same Go WASM.

We picked a Password over a passkey's PRF output, which needs browser support and is tied to the site's domain, and over a random key shown as a recovery phrase, which is a backup chore. The costs are these. The Password is only as strong as the User makes it, since anyone holding the signature can test guesses offline against the on-chain User Key, so new Passwords need at least 12 characters. There's no reset, so forgetting the Password loses every Channel. Changing the derivation, including its parameters, orphans existing Channels, as ADR-0002 warns.
